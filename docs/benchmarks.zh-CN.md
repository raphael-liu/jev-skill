# 实验数据与适用边界

[English](benchmarks.md)

**Jev 在有限选项的结构化决策中响应较快，但实验没有证明它能普遍改善完整研发任务。** 实验日期为 2026-09，配置为 Codex CLI `0.145.0`、`gpt-5.6-sol` / `medium`、Jev `jev-1.13.0`。没有测试 Claude Code；技能兼容某个 Agent 不代表已有该 Agent 的性能证据。

## 先区分实验组与组内模型

**A、B、C 表示工作流，斜杠后的 Codex / Jev 表示该工作流中被统计的模型组件。** `B / Jev` 与 `C / Jev` 使用相同版本的 Jev，但不是同一批请求，也不是两个不同的 Jev 模型。

| 组别 | 完整任务 pilot | 80 题结构化测试 |
|---|---|---|
| A：Codex 独立组 | Codex 执行完整开发、审查或问答工作流 | Codex 根据固定材料返回两字段决策 |
| B：Jev 独立组 | 补测仅得到结构化子任务判断，未交付完整任务 | Jev 返回最终两字段决策，不调用 Codex；错误或失败保留计入评分 |
| C：组合组 | Jev 提供建议，然后由 Codex 继续完成任务；Codex 不被跳过 | Jev 先判断，通过路由门槛则直接返回，否则调用 Codex 复核 |

因此，两项实验中的 C 都包含 Jev，但**只有结构化测试的 C 是可以省去 Codex 调用的条件级联**。不能把结构化测试的调用减少比例直接套到完整任务 pilot 上。

|---|---:|---|---:|---:|---|

| 真实代码审查 | 417.53 | 未完成 / N/A | 289.96 | −30.6% | C 的有证据问题覆盖较弱，不能称为同质量提速。 |

### 为什么没有 B 的完整任务耗时？

这不是漏填，也不是把 B 耗时记为零。该实验核实的 Jev System One API 仅提供 Choice、Score、Noul 结构化输出，未提供本实验所需的自由代码/报告生成与自主工具执行工作流。补测中 B 没有调用 Codex 代为交付，因此没有可与 A/C 比较的完整任务完成时间：

| 场景 | B 补测实际返回 | 未交付的完整任务产物 |
|---|---|---|
| 贪吃蛇应用 | 架构选项与边界条件判断 | 应用源码、测试执行和可运行应用 |
| 真实代码审查 | diff 块优先级 | 独立生成并论证的完整审查报告 |
| Crash 排障 | 下一步取证动作与证据充分性判断 | 自主源码调查、符号化及诊断报告 |
| 知识问答 | 外部检索材料的覆盖度判断 | Jev 自行检索并生成的完整答案；外部服务生成的文本不能归为 Jev 产出 |

B 并非完全没有调用数据：后续独立子任务补测共执行 **47 次有效 Jev 请求、0 次 API 失败、0 次 Codex 调用**。它只复用冻结请求输入，不复用 C 的响应，且不与 A/C 同期执行；这些记录不是三组同等交付物的端到端随机对照。Jev 的短判断耗时不能填进完整任务耗时列，否则会把“选择开发方案”误当成“完成应用开发”。`N/A` 表示没有等价完整交付的可比测量，不表示超时、接口报错或全场景准确率为零。

后面的 80 题实验将交付物统一为两字段决策，三组才具备共同评分口径，因此提供 A/B/C 的完整对照。这些能力边界针对当时核实的 API 和实际运行结果，不断言未来产品永远无法完成其他任务。

CSV 保留最初 `crash` 探索轮（212.73 / 252.18 秒），但公平比较排除该轮：其中可访问历史修复。`crash_fixed` 是替代对照。`rn_fixed` 仅测回答生成，不含在线检索。不要把这些替代轮次累加为独立可比任务。

真实审查中，Jev 用 43 次调用给 350 个 diff 块排序，耗时 47.73 秒、输入 428,007 tokens。某敏感文件问题排第 43，组合审查未报告。低优先级不能作为排除文件或跳过确定性密钥检查的依据。pilot 没有证明通用的端到端或总费用收益。

## 80 题结构化测试

A 为 Codex，B 为 Jev，C 为独立调用 Jev 后按路由决定是否交给 Codex。B 与 C 不共享 Jev 响应。每题只从固定选项选择 `decision` 和 `evidence`，两项均匹配才算全对；禁止工具调用与检索。这不同于开发应用、发现全部审查问题或定位真实事故。

开发集 40 题（每场景 10 题），测试集 80 题（每场景 20 题）。编码与审查题是可执行的合成微型案例；Crash 是合成证据上的显式规则判断；知识开发材料为合成规则，测试来自一份核验过的文档。测试来源组数分别为 4 / 10 / 10 / 1，因此 80 题不等于 80 个独立真实来源。审查候选已提供待核验的反例；编码 evidence 表示一致性，不代表独立定位能力。

| 场景 | A 全对数；平均秒数 | B 全对数；平均秒数 | C 全对数；平均秒数 | C 直接返回 / 错误放行 |
|---|---|---|---|---|
| 编码规则 | 20/20；9.90 | 14/20；0.94 | 19/20；5.44 | 12 / 1 |
| 受控代码审查 | 20/20；10.52 | 18/20；0.94 | 20/20；2.64 | 17 / 0 |
| Crash 证据决策 | 20/20；9.43 | 20/20；1.15 | 20/20；0.93 | 20 / 0 |
| 知识证据选择 | 18/20；9.60 | 14/20；0.92 | 17/20；4.07 | 14 / 1 |
| 算术汇总 | 78/80（97.5%）；9.86 | 66/80（82.5%）；0.99 | 76/80（95.0%）；3.27 | 63 / 2 |

C 升级 17 题。与 C 自身当次 Jev 判断相比，9 题由错变对、6 题保持正确、2 题仍错；直接返回的 63 题中有 2 题错误。编码与知识场景存在质量和延迟取舍。Crash C 全部由 Jev 直接返回，只展示规则执行，没有展示 Codex 协作增益。受控审查结果不能外推到完整真实代码审查。

开发阶段从五个候选阈值中选出 `min(decision confidence, evidence confidence) >= 0.5`，要求至少直接返回 5 题且开发错误放行为零，最终开发直接返回 34 题。**0.5 只是本次实验参数，不是生产默认值，也不是校准后的正确概率。** 测试中 confidence 为 0.79 和 0.60 的错误仍被放行。生产路由需要自己的独立验证集与错误预算，不能仅依靠 confidence。

## 按 provider 统计的 token

### B / Jev 与 C / Jev 的具体差别

- **B / Jev（独立组）**：80 题分别调用 Jev，其输出就是 B 组最终答案，没有 Codex 兜底。
- **C / Jev（级联前置）**：同样先为全部 80 题独立调用 Jev；63 题直接返回，17 题继续交给 Codex。它统计的是 C 内的第一阶段，不是整个 C 组，也不只是升级的 17 题。
- **C / Codex（升级复核）**：只统计上述 17 题的 Codex 调用。C 组完整用量需要把 C / Jev 与 C / Codex 相加，不能再加独立对照组 B 的用量。

两处 Jev 使用相同版本和相同题目请求内容，所以本轮输入 token 合计同为 62,838；但请求独立、响应不复用，记录的输出 token 分别是 9,699 与 9,687。不能要求其响应、耗时或输出计数逐项相同，也不能用 B 的结果替代 C 自身前置结果来分析“复核纠错”。例如 Crash 场景 C 没有升级，但均耗时 0.93 秒、B 为 1.15 秒，这只是独立请求的观测差异，不证明多加级联逻辑能使 Jev 更快。

以下仅统计正式 80 题测试。缓存输入已经包含在输入中；Jev 没有单独返回缓存输入计数。“合计”指输入 + 输出，不能再加缓存输入。

| 组 / provider | 输入 | 缓存输入（输入子集） | 输出 | 输入 + 输出 |
|---|---:|---:|---:|---:|
| A / Codex | 2,024,876 | 824,192 | 2,407 | 2,027,283 |
| B / Jev（独立组） | 62,838 | 未报告 | 9,699 | 72,537 |
| C / Codex（升级复核） | 430,184 | 193,152 | 1,073 | 431,257 |
| C / Jev（级联前置） | 62,838 | 未报告 | 9,687 | 72,525 |
| C / provider 算术合计 | 493,022 | 193,152，仅 Codex | 10,760 | 503,782 |

C 的 Codex 调用由 80 次降至 17 次，减少 78.75%。输入加输出的算术总量约减少 75.15%，**不等于 78.75%**：C 还调用 Jev，每次调用大小与输出也不同。不同 provider 的分词器使合计只能作为记账数量，不能视为等量工作。CLI 固定上下文、缓存及 API/CLI 协议不同，也使这些数值不能解释为模型本身的效率。没有实际账单，不宣称费用节省，也没有 Claude 对比。

全部阶段共有 A 152 行、B 152 行、C 112 行（开发阶段未运行 C）。以下仅为已返回计数之和，不是完整消耗，也不是公平的组间对照：

| 组 / provider | 已报告输入 | 已报告缓存 | 已报告输出 | usage 缺失行数 |
|---|---:|---:|---:|---:|
| A / Codex | 3,820,935 | 1,490,944 | 4,149 | 1 |
| B / Jev（独立组） | 111,150 | 未报告 | 17,215 | 10 |
| C / Codex（升级复核） | 834,612 | 497,792 | 1,558 | 0 |
| C / Jev（级联前置） | 76,930 | 未报告 | 11,866 | 14 |

失败调用缺失的 usage 是**未知，不是零**。公开 CSV 用空单元格表示缺失，零表示该 provider 未被调用。pilot 未记录 Jev 输出及缓存用量，无法补算。

## 可靠性与有效性边界

正式 240 次响应无服务或协议失败。开发 A 有一次容量失败，保留计错。预选 16 题各追加两轮，每组增加 32 次调用：B 有 10 次 HTTP 503，C 前置 Jev 有 14 次；C 回退后最终返回合法结果。重复轮不增加独立测试题数。重复子集中成功响应未观察到语义答案变化，但不能据此声称稳定。服务失败与语义错误应区分，这个短时间窗口无法估计长期可用性。

4 个并发案例共享机器，同题三组交替顺序。耗时包含 CLI 启动、路由、校验与失败响应，不含共同准备和独立评分；比较的是接入系统延迟，不是孤立的模型推理速度。题目由代理生成并由另一代理核验，不是人工专家盲标。运行目录包含题号和阶段名；事件审计未发现工具读取标签，但不是操作系统级访问审计。不宣称统计显著性、稳定 p95、校准可靠性或通用产品排名。

## 公开数据与复算

- [data/pilot.csv](data/pilot.csv)：从逻辑来源 `jev-codex-eval/measurements.csv` 按字段白名单提取，与 `measurements.json` 交叉核验；结论依据同目录 `report.md`。
- B 独立子任务补测说明依据逻辑来源 `jev-codex-eval/jev-only/report.md` 与 `jev-codex-eval/three-arm-measurements.csv`；这些后续补测未收录在本仓库 `data/pilot.csv`，该 CSV 仅含 A/C 完整工作流记录。
- [data/structured.csv](data/structured.csv)：来自 `jev-codex-eval-v2/results.csv` 的 416 行测量数据，题号及来源组映射为不透明数字。排除文本答案、标签、输入哈希、原始 ID、错误正文、来源内容与内部链接。失败调用 usage 从原记录占位零规范化为空单元格。
- 方法与汇总交叉核验依据逻辑来源 `jev-codex-eval-v2/{protocol.md,report.md,summary.json,cascade-analysis.json,repeat-stability.json}`。这些名称标识本地实验产物，不是可公开下载的文件。

在仓库根目录运行 `python3 docs/recompute.py`，仅使用标准库，不调用 API。脚本筛选 `phase == "test"`，按组和场景计算全对数、`e2e_s` 均值、直接错误数，对非空 provider 计数求和并同时报告缺失数量。pilot 变化公式为 `(C / A - 1) * 100`。CSV 保留原始精度，表格显示四舍五入值。

本次公开支持**汇总算术复核**，不等于完整实验复现：私有原始材料、提示词、原始响应、oracle 和原评测器未公开。pilot 的定性验收结论及 HTTP 失败分类来自源报告，不能仅靠去敏测量数据独立重建。
